# 影片订阅追更与115增量转存设计

日期：2026-11-12
状态：方案与每日18:00时间已获用户确认；书面规格已获批准，进入实现测试；尚未上线启用。

## 1. 目标与边界

用户关注剧集/动漫并选择115中的剧集季目录后，由本站服务端每天检查更新，只将缺失新集保存至该目录，再通知已配置的OneStrm扫描。关闭网页不影响执行。

本期“续集”指同作品、同一季的新集，不自动跨季，不自动收集电影续作。只自动转存115分享，不将磁力离线提交当作转存完成，不重复实现STRM生成或Emby刮削。

## 2. 已确认方案

- 优先枚举用户关注的固定分享及所选源目录；补充使用现有搜索服务发现其他来源。
- 固定来源也必须校验文件的季、集、版本及资源规则，不能整包重存。
- 搜索来源仅在作品、年份（如配置）、季数、集数、清晰度和字幕要求明确匹配时自动转存。缺少必要信息或存在冲突则进入待确认，不靠模糊片名自动写盘。
- 创建订阅时明确选择115目标目录，绑定实际目录ID并保存路径快照。服务端确认目录属于当前115账号且存在；目标不存在时阻止写入，不回退到根目录。
- 初次处理提供“补齐缺集”和“仅后续新增”，默认后者。后者需先完成源文件基线采集；初始化失败不能把全部旧文件当新集。
- 重命名、去广告和删除旧版本不纳入自动追更，避免影响原有媒体及字幕对应关系。

## 3. 调度：每天北京时间18:00一次

- 固定时区Asia/Shanghai，和宿主机、Docker、浏览器时区无关。
- 每天18:00启动一轮，分批处理所有启用的订阅；18:00为开始检查时间，并非所有任务完成时间。
- 不进行每30分钟或其他频率的自动资源检查。保留“立即检查”，只作用于当前用户指定的订阅。
- 数据库保存北京时间运行日期，单个订阅当日自动检查仅领取一次。手动与自动检查共用互斥规则，不并行转存同一集。
- 若服务在18:00停机，本期不自动补跑错过的整轮，到下一次18:00检查；用户可手动补查。未完成写盘操作在恢复后先核对目标目录，不能盲目重发。
- 进程重启、按钮连点或重叠实例不得产生重复写入；持久化运行记录与锁，不能仅依赖内存定时器。

## 4. 页面交互

- PC和手机搜索结果新增“关注追更”；仅对可识别115分享开放自动转存入口。
- 新增“我的追更”页，严格按登录用户隔离。
- 配置：作品名、明确别名、年份（可选）、季数、资源要求、源分享/提取码/源目录、目标目录、首次处理模式、启用状态。
- 展示：每日18:00、下次检查、最近检查、发现集数、已存集数、待确认项及失败原因。
- 操作：创建、编辑、暂停/恢复、立即检查、查看记录。移除订阅不删除115文件。
- 更换来源、目标目录或115账号后重新校验/建立基线，旧记录不跨账号或跨目录复用。

## 5. 后端职责与持久化

沿用Express + Sequelize + SQLite及现有请求级115 Cookie。新增订阅模型、运行记录、逐集处理记录与服务端调度模块。

- 订阅记录：归属用户、115账号标识、作品身份、季、来源、资源规则、源基线状态、目标目录ID、启用状态、最近自动日期和错误。
- 运行记录：订阅、自动/手动、运行日期、开始/结束时间、锁与处理结果；自动日期唯一约束防重复。
- 逐集记录：源分享文件ID、文件名、集/季、内容哈希（如提供）、大小、目标目录/文件ID、写入状态、核实结果、OneStrm通知状态。
- 集级去重键包含订阅/账号/目标目录/季/集；相同内容哈希的不同链接不重复转存。
- 大整数文件/目录ID全程以字符串保存和传输，不能先转Number再转回字符串。
- 当前115分享读取只取首20条，目标目录读取存在首屏限制；实施前必须补齐分页、目录遍历以及fid与cid的正确区分。
- 当前转存只发送fids首项；新增追更应逐个发送已确定的文件ID，不能复用整目录转存假定。

## 6. 增量确认与安全

1. 加锁、检查启用状态，校验当前115账号及目标目录。
2. 分页读取目标目录已有媒体，识别明确的季集信息；未知文件不能被当作不存在。
3. 分页读取固定分享，必要时补充搜索候选；限制并发、遍历深度、文件数量及超时。
4. 根据源基线、内容信息、季集号和成功记录确定缺集；合集包含多个集且无法拆分时待确认。
5. 转存单集；写请求超时标为“结果待核实”，先查目标文件再决定后续处理。
6. 只有读取目标目录核实成功，才持久化为“转存已确认”。失败不覆盖已有文件，不通过改名操作目标目录中的同名旧文件。
7. 一批确认成功后调用OneStrm一次；通知失败单独记录，不回滚或重复转存。
8. 保存结果、释放锁。暂停订阅后停止新的写操作；在途请求仍须核实并记录。

115授权失效、风控、源分享取消、目标目录缺失、识别不确定分别展示，不混为“没有更新”。授权失效暂停自动写入，重新授权且账号匹配后才允许恢复。错误日志不记录Cookie、提取码、令牌或管理密码。

## 7. OneStrm状态语义

“已通知扫描”不等于“STRM已生成”。现有全局日志最近30条加标题匹配不足以证明某一集完成。本期订阅只展示可证实的“未通知 / 已通知 / 通知失败 / STRM待核实”；如获得与目标文件精确关联的证据，可增加“已确认生成”。不以同名历史日志或一次全盘扫描成功认定该集完成，不向用户返回其他用户的全盘日志。
